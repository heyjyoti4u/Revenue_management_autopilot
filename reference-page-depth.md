# Reference Page-Depth Findings

## Revenue management route
The page is a long-form service page with a conversion-oriented hero, repeated free-consultation CTAs, an explanatory section about the operating gap, a step-by-step revenue loop, a detailed operational proof section, a pricing/rate interface surface, compatibility with existing dynamic-pricing tools, channel-level considerations, lead-time or alert content, communication examples, an included-services matrix, integrations, FAQs, and a closing conversion block.

## OTA optimization route
The reference route uses a distinct channel-led visual system: a dark green hero, large editorial headline, direct service promise, and a compact channel-mix interface card comparing Airbnb, Booking.com, Vrbo, and Expedia. It continues into a section explaining the distribution gap, channel-specific operating blocks, proof/strategy details, and a CTA focused on a free channel review. The page is materially different from the revenue-management route in both artifact and narrative.

## Implementation implications
SignalStay should not use one identical interior template for every route. The STR revenue page should include a rate-window artifact, revenue-loop steps, compatibility content, operating matrix, FAQ accordion, and conversion panel. The OTA page should include a channel-mix artifact, platform-specific panels, distribution-gap narrative, and channel-review CTA. Hotel pages should use a commercial revenue-desk artifact and team handoff content. Resources should use an editorial library structure. Customers should use outcome snapshots without fabricated testimonials, ratings, or reviews. Booking should use a review brief and form rather than a generic feature grid.
